# Pilot #1 — Personal Developer Portfolio + CV + Projects + Writing

Status: *brief only; implementation not yet performed*.

## Product goal
Create a personal professional website for recruiters and engineering teams. A visitor should rapidly understand what the developer does, inspect tangible projects, find a factually accurate CV, and read occasional technical writing. It is a presentation site first, not a full SaaS dashboard.

## Confirmed working context (only use after the user validates publication wording)
- Technical direction: software developer with a backend focus, especially C# / .NET.
- Project example 1: Logo-integrated e-document template/design tool for e-invoice / e-archive workflows.
- Project example 2: OzBackup, a backup-oriented product with email/SMS integration.
- Intended site surfaces: homepage/about, work/projects, CV or experience when factual information is provided, and writing/blog.

Do NOT infer job titles at named companies, tenure, customer counts, project screenshots, metrics, testimonials, diploma dates, certifications, published blog articles, GitHub profiles, LinkedIn addresses, phone, email or downloadable CV. Leave as content-needed, or hide until verified. Do not assume the user wants to publicize every private detail.

## Priority information architecture
1. Home: clear developer positioning + selected project proofs + purposeful next step.
2. Projects: verified feature summaries and authored screenshots, each with problem/approach/role/outcome only where confirmed.
3. About / CV: concise professional summary; experience and certifications only when provided; CV download only with real file.
4. Writing: article listing and reading page when posts exist. Do not invent fake posts to fill the grid.
5. Contact: real contact channel only after supplied; no nonfunctional form or fake inbox.

## Visual problem to solve
Earlier concepts across projects looked like generic AI-generated websites: repeated dark themes, blue-purple gradients, same-sized rounded cards and predictable hero arrangements. The new site must convey intentional editorial structure and project credibility. **Do not pre-impose a specific visual style**, including 'Evidence First', before exploring three structurally different directions.

## Concept hypothesis examples (not design prescriptions)
- Editorial case-study portfolio: typesetting-led narrative with generous margins and selected project screenshots.
- Technical index/catalog: structured and accessible content navigation with deliberate density.
- Visual monograph: sparse graphic identity, unusual but usable grid, project artwork as narrative anchors.
All three MUST be independently art-directed; these are only prompts for exploration, not guaranteed outputs.

## Acceptance
- Mobile-first reading and navigation, desktop presentation quality.
- No AI-slop default pattern without rationale, no invented facts or placeholding fake professional achievements.
- Rendered screenshots at three widths, keyboard review, contrast evidence, console checks and diff audit.
- One human decision on selected direction before committing to the complete portfolio.

## To discover from actual repository
- Framework/version, installed browser tooling, current routes, styles and design tokens.
- Protected backend paths and legal UI edit paths.
- Existing source CV, project images, screenshot assets and public links if the user supplies them.
